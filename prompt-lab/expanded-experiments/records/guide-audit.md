# GPT Image 2.5 guide audit and experiment coverage

Audited 10 September 2026. This is an inventory and proposed experimental design, not a result report. No images were generated by this audit.

The current selected [GPT Image 2.5 guide](https://developers.openai.com/api/docs/guides/image-prompting?model=gpt-image-2.5) has **24 illustrated prompt steps**: nine generation examples, eight editing examples, four steps in longer workflows, and three additional workflows. Its character workflow contains two steps under one heading. Its logo example shows four variants from each model under one prompt. There are **54 official output images and 11 unique input assets**. The runnable examples repeat logo generation and product extraction; they do not introduce additional creative tasks.

The companion `guide-inventory.json` provides every heading, source anchor, source prompt hash and line, settings, source image URL, input role, proposed richer trial, and acceptance checks. All 65 unique asset URLs responded with HTTP 200. Accessibility checks do not establish visual quality; the assets were not visually graded in this audit.

## What the source supports about 2.5

OpenAI's [announcement](https://openai.com/index/introducing-chatgpt-images-2-5/) describes improved reference likeness, targeted editing, multi-turn retention, natural light and texture, complex layouts, and faster generation. It introduces Sketch, image comments, templates, and prompt sharing in ChatGPT. These are vendor claims and product features, not results of our tests.

There is a wording discrepancy worth preserving: the announcement describes Flare as higher quality than Image 2 and reports 50% lower latency; the operational prompting guide calls its quality comparable to Image 2 and instructs developers to measure their own workload. The defensible article wording is that **Flare is positioned for speed and Sunburst for demanding quality; actual gains depend on the task**. Do not turn a launch claim into a universal measured advantage.

The [API guide](https://developers.openai.com/api/docs/guides/image-generation#size-and-quality-options) confirms that the two 2.5 models add `xhigh` and `max` quality levels; earlier models top out at `high`. Dimensions and transparency remain explicit request settings. Resolution above 2560 × 1440 is experimental. Transparency and reference editing are not entirely new capabilities: the Image 2 reference already supports them, with transparency marked preview.

The [system card](https://deploymentsafety.openai.com/chatgpt-images-2-5) also describes editing consistency and infographic improvements, but its published quantitative tables concern safety outcomes on an adversarial prompt set. Those numbers cannot be repurposed as aesthetic quality, reconstruction fidelity, or prompt-method improvement scores.

The [API limitations](https://developers.openai.com/api/docs/guides/image-generation#limitations) still identify precise text, recurring subject consistency and placement as weaknesses. A reconstruction JSON cannot promise exact pixels or guarantee fidelity.

## Four comparisons that answer the user's questions

### 1. Plain language, structured language and visual references

Use one approved scene specification. Produce three prompts carrying the same visible requirements: short plain sentences, labeled sections, and the prose compiled from reconstruction JSON. Keep the image inputs, model, dimensions and available generation settings the same. Count semantic requirements before generating: if the structured prompt adds ten constraints, an improvement demonstrates the value of extra specification, not a benefit from headings or JSON punctuation.

Then run a distinct information experiment: identical text with no image, a full reference, and selected reference crops with named roles. Those arms answer what visual evidence contributes. Do not describe this as a language-format comparison.

Good high-information cases are G02, G06, G12, G17 and G22. They expose different failures: graph relations, sequence, identity binding, action/depth and object selection. Choose the same criteria before inspecting any output.

### 2. One element at a time versus one combined edit

Start from the same approved image and prescribe the same final goal. In the sequential arm, make changes A then B. In the combined arm, request A and B together. Compare final correctness, drift in locked elements, time and total generation calls. Sequential editing has a diagnostic advantage, but it adds another opportunity for drift; it is not automatically superior.

Use an independent pair such as chair material plus wall paint, and a coupled pair such as sunset-to-winter lighting plus snow cover. Material and lighting changes may legitimately affect reflections and shadows. Locking those pixels absolutely while requesting a different light environment creates contradictory instructions.

After failure, isolate the smallest causal correction and return to the best accepted source. Do not accumulate failed edits. If one arm receives a repair, either give the other a matched repair budget or report the unequal budgets explicitly.

### 3. Reconstruction JSON and interactive visual mapping

For a complex reference, create stable element IDs and a scene hierarchy: canvas, regions, objects, parts, labels, relationships, light, materials and background. A named crop is evidence of an element's appearance; a bounding box is only its approximate location. A crop containing several overlapping objects is not an isolated transparent extraction. Label those distinctions visibly.

Let the reader select which IDs to preserve, replace, remove or borrow. Their selection should update both the JSON and the compiled prompt immediately, while showing the referenced crops. Retain parent-child and occlusion relationships so selecting a person's jacket does not accidentally transfer the entire person or setting.

Unknown backside geometry, illegible text, hidden objects and inferred lighting belong in explicit uncertainty fields. The reconstruction should preserve what is observed and identify what the generator must invent. Prefer reconstruction goals such as recognizable composition, subject likeness or exact layout over a single unqualified word like identical.

This methodology is an authored workflow. The guide's acceptance of JSON-like prompts does not mean GPT Image has a native reconstruction-JSON schema, parses our element IDs as segmentation masks, or guarantees coordinates. Validate the generated image against the selected element requirements.

### 4. Sub-agents for combinations of references

Use bounded branches with a common brief and common evaluation sheet. One agent can keep the complete reference, another use only selected identity/material crops, and a third combine a layout reference with a separate style reference. Every branch records exact inputs and their roles. A reviewer compares outputs without knowing which branch authored them where possible.

Sub-agents organize parallel search and independent criticism. They do not themselves create a new control mechanism inside the image model. To claim an advantage over one agent, match the total number of generated candidates and the available references. Otherwise the experiment only shows that spending more samples can yield another good option.

Avoid a combinatorial explosion. With five candidate references, trying every subset would require 31 nonempty combinations before prompt variants. Test three reasoned hypotheses first, then refine the one that meets the brief. Record losing branches rather than publishing only the favorite.

## Reporting boundaries

- Mark published source images, our raw generations, our edits and deterministic overlays separately.
- Do not call an image a verified 2.5 run unless the executing UI or API exposes enough evidence of the model. Product rollout language is not per-request provenance.
- Distinguish the native `@Sketch` user interface from uploading a drawing as an image reference. Both can supply spatial guidance; they are not the same UI test.
- Use pass/fail/uncertain per requirement, supplemented by a separate aesthetic preference. A more dramatic picture may reconstruct the reference less accurately.
- Report worse, tied and improved cases. One attractive output cannot establish a general improvement percentage.
- A generation-only sample is not a usable interface, valid scientific model, proven historical document or editable chart. Verify the deliverable appropriate to its use.
- Record actual dimensions, alpha, prompt, source inputs, selected elements, edit ancestry and exposed model/settings. Mark unavailable settings unknown.
